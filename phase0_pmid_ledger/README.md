## 3. Google側で必要な設定・承認

**現在、ご本人による承認とスプレッドシートへの読み書きまで確認済みです。追加設定は不要です。** 以下は新たな端末で承認が必要になった場合の手順です。

1. 上のTEST Webアプリを、ご本人のGoogleアカウントで開く。
2. `Review Permissions` を選ぶ。作成直後の本人用GASのため、「このアプリは Google で確認されていません」が表示される。
3. アプリ名が上記TEST名、開発者がご本人のメールであることを確認する。信頼できると判断した場合のみ、ご本人が詳細から承認へ進む。不一致や予期しない権限があれば中止する。
4. 求める権限は次の2つのみ。**Googleのスプレッドシート権限自体はアカウント内全体に及びます。コードによるアクセス先制限と、OAuth権限の範囲は別です。**
   - `https://www.googleapis.com/auth/spreadsheets`
   - `https://www.googleapis.com/auth/userinfo.email`
5. スプレッドシートへのアクセスも許可したことを確認し、Webアプリを再読み込みする。アプリの枠が表示されるだけでは全権限の承認確認にならない。本人確認エラーなら、使用中アカウントを確認する。公開範囲を「全員」に広げて解決しない。

初回の未確認アプリ警告と追加権限は、ブラウザ操作スキルの安全上の制約に従ってご本人の操作に引き継ぎ、承認後に検証しました。

## 4. iPadでの確認手順

**TEST用です。出力ファイルを `pubmed-grarec-notion` で実処理しないでください。**

1. SafariでTEST Webアプリを開き、Macと同じ本人アカウントでログインする。Google Docsアプリ内のブラウザで不安定な場合はSafariで直接開く。
2. 初期タブが「最近の未確認」で、PMID 1・2、タイトル、分野、日本語状態が表示されることを確認する。各区分の件数も確認する。
3. PMID 1の「配信時の要約・掲載履歴」を押す。8月と6月の2つの要約・当時タイトル・配信IDが別々に表示されることを確認する。
4. PMID 2の詳細を開き、一行評価が表示され、要約の空欄が「保存なし（再生成はしません）」になることを確認する。
5. PubMedと「Googleドキュメント（現在版）」を開く。別タブまたはOSのリンク処理で開けることと、元の一覧に戻れることを確認する。CURRENTは過去の本文を保証しない。
6. 「次の保存を失敗させる」をチェックし、PMID 1を原文入手希望に追加する。赤い失敗表示になり、成功メッセージが出ず、再読み込み後も未確認であることを確認する。
7. チェックを外して再度追加する。成功表示後、「原文入手待ち」に移動し、Safariを再読み込みしても希望状態が残ることを確認する。Macから開いても同じ状態であることを確認する。
8. 「原文入手希望をTXT出力」→「pmids.txtをダウンロード」を押す。Safariのダウンロード一覧／ファイルAppで確認する。初期サンプルのPMID 10と、手順7で追加した1が、`1`、`10`の順に1行ずつ入る（末尾改行あり）。タイトルなどは入らない。
9. PMID 20が3か月より古くても「原文入手済み・未読」に残ることを確認する。必要に応じて他の状態へ変更し、再読み込みを確認する。TESTメモは残る。
10. iPadの縦向き・横向き・Split Viewで、横スクロールなしで読めるか、ボタンを押し間違えないか、詳細を閉じられるかを確認する。
11. 競合確認：MacとiPadで同じPMIDを表示し、Macで先に保存する。古い表示のiPadから別状態を保存したとき、上書きせず再読み込みを求められることを確認する。

オフライン保存は対応していません。応答が20秒以内に返らない場合は「保存結果は不明」と表示します。成功と見なさず、再読み込みまたは同じ操作の再試行で確認してください。ダウンロードしただけで原文入手済みには変更しません。

## 8. pubmed-pdf-fetcherとの互換性

2026-08-30、ユーザー指定の隣接リポジトリ `pubmed-pdf-fetcher` の `src/utils.py`、README、`input/pmids.txt` を読み取り調査した。`extract_pmids` は、先頭の空白を除いた行が `#` で始まる場合、その行を処理対象から除外する。したがって `# 1` は取得対象にならず、`1` のようにPMIDだけを記した行が対象になる。現在の出力形式とファイル名 `pmids.txt` は変更不要。

取得処理を起動せず、実際の読み取り関数だけで以下の3例を確認した：数字のみの `1\n10\n` → 2件、`# 1\n# 10\n` → 0件、見出し・取得済みコメント・重複を混ぜた例 → 有効なPMIDだけ1件。ネットワーク・OpenAI API・PDF取得は実行していない。隣接リポジトリと既存の入力ファイルには書き込んでいない。

本番運用ではMacで取得する `pmids.txt` を同アプリの入力に渡せる。既存入力ファイルに残る未処理PMIDを失わないよう、無断で上書きしない。Phase 0の架空データは実処理へ渡さない。
